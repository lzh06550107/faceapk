# 同步、人脸索引与页面生命周期修复设计

## 范围

本次只修复审核问题 3、4、5、8，不处理其他审核项。

## 设计

- 人脸 SDK 的整数 ID 不再由员工编号解析或哈希生成。新增 `face_sdk_ids` 表，以员工编号为主键、SDK ID 为唯一值；首次使用时分配递增正整数，删除员工不回收映射。
- 用户手动同步可以随时重置已达上限的重试次数。自动触发（心跳、启动、网络恢复、打卡后）只重置 `last_retry` 早于设备本地当天零点的记录，因此每条记录每天最多获得一轮新的自动重试机会。
- 心跳和打卡上传使用不同的单线程执行器。每次上传最多读取 50 条，并受 30 秒批次预算约束；网络传输错误发生后立即结束本批次。
- Fragment 的异步工作记录 View 代次。页面销毁后关闭该代次、取消待执行回调或任务，旧代次结果不得更新新页面或已销毁 View。
- 在线统计请求统一通过触发白名单进入：面板就绪、用户进入面板、查询条件实际变化、加载下一页、用户主动刷新。`onResume`、Spinner 初始化和其他原始生命周期回调不得直接请求；相同活动查询合并为一次。

## 验收

- `"1"`/`"01"`、`"Aa"`/`"BB"` 获得不同且重启后稳定的 SDK ID。
- 自动周期当天达到 3 次失败后停止重试，跨入下一个本地自然日后恢复一次；手动同步仍可随时恢复队列。
- 大队列不会阻塞心跳请求，单批读取数量有上限，传输故障快速退出。
- Records 和 Punch 页面销毁后，旧异步结果被丢弃且不持有旧 View。
- Records 面板初始化或重建时，同一查询最多存在一个活动请求；旧查询响应不能覆盖新筛选结果。
